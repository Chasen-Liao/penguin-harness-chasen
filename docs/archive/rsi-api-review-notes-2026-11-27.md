# RSI API 设计评审清单 · 2026-11-27

| 状态 | 议题 | 修改方向或待讨论的问题 |
|---|---|---|
| 本版已改 | 首轮闭环 | 在开源 Codex CLI 上选一个具体任务，跑通 Skill 优化闭环，用同一套 Benchmark 比较前后表现。 |
| 已明确方向 | Session 拉取 | 已知来源和 session ID 时，内部可主动拉取该会话截至读取时能提供的历史。运行中通过 Hook 分批推送是另一条采集路径。两者汇入同一 session。 |
| 已明确方向 | Trace 用途 | 内部 ISI 用它分析任务是什么、Skill 怎么用、在哪一步产生了什么可观察的结果。区分已安装、被加载和有实际使用证据的 Skill。单次 trace 可以解释过程，效果提升还需基线对照。 |
| 初步方向 | 子 Agent | 将可识别的子会话作为独立任务，用父子关系还原任务树。子会话不可读时如何表示、是否递归拉取，待讨论。 |
| 待改 | 发现、分页与去重 | 将按 ID 读取与按项目、更新时间段发现会话分开。后者分页，移除公开的 cursor 和 next_cursor。定义稳定的来源与会话标识、重复推拉和旧快照处理。 |
| 待改 | Hook、范围与来源 | 简化 delivery 的解释。梳理项目绑定后 scope、workspace 是否重复，保留可用的原始磁盘路径。按既有部署条件说明双向连接。 |
| 待改 | Skill 与评测 | 核对 AMCP 与仓库 AmspRecord 的对应关系，active_skills 先保留。用多文件示例解释 SkillBundle；merge 按 Skill 文件夹名取并集，说明同名目录的更新规则。解释 VerificationProof、帕累托改进与人工放行。 |
| 待改 | 适配范围及配套说明 | 去掉 Cursor 适配示例；协议定稿后同步方法表、错误恢复、工作台流程与 HTML 展示稿。 |
| 下轮重点 | API 只能返回部分信息 | 区分可读内容、无权限、不支持和暂未同步。讨论哪些证据足以分析某项 Skill，何时只能将作用记为未知。 |
| 下轮重点 | 离线保证 | 分别约定 RSI 已确认入库的数据、外围已采集但未送达的数据、来源从未开放的数据。讨论可重读来源的补拉、一次性数据是否需外围落盘，以及恢复后如何报告缺口。 |
